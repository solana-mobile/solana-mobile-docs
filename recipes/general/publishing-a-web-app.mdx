Web apps can be published on the dApp Store by wrapping them in an Android WebView shell and submitting the resulting APK. The [`solana-mobile webshell`](/cli/webshell) command generates that Android project and builds a signed release APK from it.

<Note>
  A WebView shell needs no Digital Asset Links setup, and it keeps Mobile Wallet
  Adapter working: browsers are rolling out [Local Network
  Access](https://developer.chrome.com/blog/local-network-access) restrictions
  that break wallet connections for web apps, including Trusted Web Activity
  wrappers such as Bubblewrap APKs. The shell handles wallet intents natively
  instead.
</Note>

<Steps>
  <Step title="Host your web app">
    Make sure your web app is reachable at a public URL. If it has a [web
    manifest](https://developer.mozilla.org/en-US/docs/Web/Manifest), the CLI
    seeds the app name, icons, and start URL from it.
  </Step>
  <Step title="Update Mobile Wallet Adapter">
    Update `@solana-mobile/wallet-standard-mobile` to **v0.5.1 or later** so
    your app detects the shell and skips the browser permission flow. See [Local
    Network Access](/recipes/mobile-wallet-adapter/local-network-access).
  </Step>
  <Step title="Wrap into an Android APK">
    Run [`webshell init`](/cli/webshell#webshell-init) to generate the project
    and [`webshell build`](/cli/webshell#webshell-build) to produce a signed
    release APK.
  </Step>
  <Step title="Publish to the dApp Store">
    Submit your signed APK through the standard dApp Store publishing process.
  </Step>
</Steps>
